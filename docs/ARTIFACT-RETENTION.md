# 发布产物与空间管理

范围：治理发布/构建产物；不改变研迹业务、数据库或数据迁移规则。2026-10-14 空间审计首次落地。

## 保留规则

- 长期保留源码、Git 历史/标签、依赖锁文件、许可证、数据库语义/迁移/恢复测试源码。
- 固定保留 V0.2.2@81eea673（已验证回退基线）、V0.3.0@869e410c（原始计时显示故障程序和定位证据）、V0.3.1@40022179（修复版本及红/绿证据）。不得因为版本更新自动解锁这些保留项。
- 每个正式版本只建立一个 `releases/<version>-<commit>/`，保留 Windows ZIP、源码 ZIP、审核 ZIP、测试证据 ZIP和原始清单/报告。不同提交不得仅因版本号相同相互覆盖。
- 工作目录只保留一个当前可用的解压运行副本。历史副本先逐文件 SHA-256 对应保留 ZIP，确认无额外证据后才进入可批准清理清单。
- 没有对应 ZIP 的旧版、候选版和旧视觉样板先封存自身运行包，不能仅凭“可以重新编译”删除。封存后重新从封闭 ZIP 校验所有条目及程序来源。
- 旧正式 ZIP建议转入独立归档位置（例如 `D:\Archives\yanji`，仅为建议，未创建/移动）。同盘移动只减少项目目录大小，不释放该磁盘空间。
- 数据库、WAL/SHM、备份、升级/恢复隔离样本默认保留，清理工具不得读取内容、自动移动或删除。`.git` 永远不在清理范围。

## 构建与证据目录

- 一次发布只使用一个活动 staging 构建目录。新的尝试先复用可安全重建输出，不用不断创建完整运行库副本。
- 红灯、异常和中断证据不可覆盖；按 run-id 存储。保留原始 TRX、checks/samples/provenance、失败日志、相关截图、清单与差异说明。
- 成功证据精简到相关场景，保留原始结果；代表性截图进入审核包，其余完整截图进入单一证据归档。comparison.html 的相对图片引用和哈希清单必须随包保留。
- 相同 ZIP/图片即使哈希相同，也要检查历史引用和清单关系后才能清理；原始失配清单与修正说明不能当“旧缓存”删除。
- 归档必须记录实际新增空间，候选目录体积不能直接作为净释放空间。

## 只读空间检查（已实现）

```powershell
python .\tools\Audit-ProjectSpace.py
# 指定新的输出位置；已有输出目录会被拒绝，历史报告不覆盖。
python .\tools\Audit-ProjectSpace.py --output .\artifacts\space-audits\release-<run-id> --warn-gib 3
# 在未来发布流水线中可选择超限返回非零；它仍不会删除任何文件。
python .\tools\Audit-ProjectSpace.py --output .\artifacts\space-audits\gate-<run-id> --warn-gib 3 --fail-over-budget
```

无需额外依赖或系统配置，复用已有 Python。报告文件包含逐文件元数据、全部目录汇总、超过 100 MiB 文件及根目录汇总。使用 NTFS AllocationSize 和文件 ID，跳过 reparse point，不进入目录链接；不读取数据库内容。MFT/目录索引/备用数据流不在统计口径内。输出写入全新的目录，默认 artifacts 已被 Git 忽略。

目标阈值：全项目约 3 GiB以内；artifacts 尽量≤1 GiB、非活动构建缓存≤0.7 GiB。阈值超限仅告警；当前历史积累需要另行批准清理，不自动删除。

## 构建缓存清理（本轮未执行）

常规命令，在不运行构建/测试后由开发者明确执行：

```powershell
& .\tools\Invoke-Build.ps1 -Arguments @('clean','YanJi.slnx','-c','Release')
```

`dotnet clean` 不等于完整删除全部旧 bin/obj 或发布产物。需要彻底清理时，用已审查的逐路径清单：重新确认绝对路径在项目内、无 reparse point、没有正在使用它的进程、无数据库/证据、对应源码/ZIP保留；再取得针对该清单的清理授权。禁止 `git clean -fdx`、根目录通配删除、清理 NuGet 全局缓存或修改 Git 历史。

## Git 与发布结束检查

- 现有 .gitignore 已覆盖递归 bin/obj、artifacts/releases、TestResults、常用数据库/备份/日志；本轮未更改规则。
- 建议后续补充 `*.sqlite3` / `*.sqlite3-*`；项目之外放入的 ZIP 不自动被忽略，必须坚持归档路径约定。不要用全局 `*.zip` 误隐藏未来合法模板/测试资源。
- `*.png` 广泛忽略，只有 `docs/*.png` 白名单；需要纳入源码的原生图片应明确增加资源目录白名单，不能因忽略规则漏交付。
- 每次发布结束：验证 ZIP 所有条目 → 确认源码提交/Tag/程序哈希 → 核对审核页依赖 → 输出空间报告 → 生成非重叠清理候选列表。清理授权是独立动作，不由发布脚本隐式执行。
- Git 暂存前检查不应包含 bin/obj、DLL/EXE/PDB、数据库/备份、临时测试输出。大于 10 MiB 的跟踪文件应阻止误入；小型有许可的 Skill 数据资源可以明确保留。
