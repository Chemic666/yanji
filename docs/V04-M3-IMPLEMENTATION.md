# V0.4 M3 实现说明

范围：隔离开发学习闭环；不实施M4，不操作真实学习数据。

## 已实现

- 学习记录唯一主要节点沿用 `sessions.chapter`，新增档案、可选任务、学习时路径与弱点关联上下文；首次保存捕获，后续计时检查点沿用。
- 从知识节点或今日任务一键开始，最近学习开始新一段；任务未指定节点会清空旧选择。自由、倒计时、番茄统一保存，主/迷你窗口沿用同一状态。
- 完成即保存，可选补充备注、薄弱点、学习状态，全部可跳过。补录可关联任务，仍不虚构时间区间。
- 记录关联可修正、解绑并保留修订；知识节点与记录双向跳转，归档后历史可访问。任务后来改名或换节点不重写已有记录。
- 知识详情展示自身/子树时长、有效次数、最近日期、未关联时间及相关任务/记录/弱点；按稳定ID集合与原始片段去重。
- 新增薄弱点和记录关联同一事务；失败完整回滚。掌握程度、已学习、完成任务、验收仍独立。
- Schema4候选迁移、旧格式备份恢复与严格版本拒绝，保留原计时、SQLite事务、修订、知识包三方保护机制。

## 主要实现位置

`src/YanJi.Core/LearningContext.cs`、Models、TimerMachine；Data中的LearningSchema/LearningMigration/Learning及原SaveRecord/SaveTimer/备份事务；App中的MainViewModel.Learning、MainWindow.Learning、KnowledgeWorkspace与现有Focus流程。技术栈和依赖不变。

## 独立审查与修正

一次只读独立审查确认两项Important：知识页再次进入不刷新学习事实、已删除记录仍保留完成补充提示；另发现最近学习错误排除最新已完成计时。真实WPF复现 `review-red` 为3 FAIL / 1 PASS，修正后相同4项均PASS。没有重复委派审查。

初次原生验收按钮查找发生在主题重建期间，现等待布局稳定。另一轮脚本在目标完成但持久化尚忙时开始下一模式，导致读到前一记录；改为等待活动与Busy均结束。原始FAIL及采样保留。截图检查还发现一次最小化标题栏截图，未作为最终视觉证据；最终捕获强制恢复本应用窗口并验证物理尺寸。

## Skill 实际使用

显式读取已安装的 `yanji-domain-rules` 与WPF参考，约束单一片段事实、未知时间、历史修订及备份边界；复用执行计划、调试、测试与独立代码审查工作流。通过文件SQLite事务故障、迁移回滚及真实HWND采样落实规则。未安装新依赖或Skill，未声称当前C目录会话自动加载D目录全部项目Skill，也未把读取指导称为运行设计引擎。
