# 正式数据目录与隔离测试修复

基线：5d6e2a0737f7c094d13cca65ca9faddd33c2504f。
程序集：0.4.0-rc.quiet.2+runtime-isolation.1；运行时仍为10.0.13。
结论：本项修复的定向验收通过；不是整体公开发行批准。

## 运行规则

| 场景 | 原实现 | 本轮实现 |
|---|---|---|
| 普通启动 | 程序旁data-rc-quiet | Windows标准LocalApplicationData目录下的YanJi |
| 指定数据目录 | 单独--data-dir可用 | 必须同时显式--test-mode |
| 自动化/截图/冒烟 | 多种诊断参数，曾有默认路径例外 | 必须--test-mode及独立绝对数据路径，无默认回退 |
| 主窗口 | 固定“隔离候选” | 普通为“研迹 YanJi”；测试为“研迹 YanJi · 隔离测试” |
| 迷你窗 | 无运行环境标识 | 测试窗口标题及面板文字均标识“隔离测试” |
| 数据搬运/升级 | 构造器不自动迁移 | 保持不自动迁移，并在可写打开前增加只读预检 |

普通启动双击YanJi.exe即可。目录不取决于ZIP名称、程序名称、程序位置或当前工作目录。
候选人工试用仍请显式执行：

```cmd
YanJi.exe --test-mode --data-dir "D:\YanJi-Isolated-Trial"
```

缺少/重复参数、相对路径、正式目录及其祖先/子目录被拒绝。检查路径现有祖先的目录联接/符号链接，并展开8.3名称重新核对；不接受测试网络共享/设备路径。不自动将旧data-rc-quiet搬到正式目录。

初始化顺序：解析参数 → 确定运行模式与绝对目录 → 校验测试数据/诊断输出路径 → 只读数据库预检 → 单实例 → 原有数据服务 → 窗口。无效测试启动不会退回正式目录；未通过路径校验的诊断输出也不会写入。

## 旧数据兼容

- `git show v0.3.1:src/YanJi.App/App.xaml.cs`确认旧版默认也使用LocalApplicationData/YanJi。故正式目录中可能已有旧库，不能假设为空。
- 当前`YanJiDatabase.cs`构造器仅接受Schema4，迁移是独立显式机制。本轮未调用迁移、升级副本或恢复入口，也不更改Schema定义。
- 新`YanJiDatabase.Startup.cs`先以SQLite ReadOnly连接验证application_id、精确Schema版本、结构及quick_check；旧格式/未知格式、损坏/零字节文件、非空但缺少主库的目录、链接目录/文件均拒绝。
- 新空目录可由原有构造器初始化。兼容Schema4可重新打开。不会因旧库拒绝而重建、覆盖、清空或自动备份/迁移。
- 旧格式需要未来独立授权的升级流程及完整备份，本轮只是拒绝，不宣称已经升级成功。

## 实际修改

- `RuntimeLocation.cs`：纯路径/标题策略及访问前的测试路径安全校验；测试用虚构Windows用户根目录验证正式路径，不打开真实目录。
- `App.xaml.cs`：显式测试开关；所有诊断启动受约束；在数据服务之前接入预检；仅向已校验的诊断输出写入失败日志。
- `YanJiDatabase.Startup.cs`：单独的只读启动门禁，复用已有身份/结构检查，不改变事务或迁移实现。
- `MainWindow.xaml/.cs`、`MiniTimerWindow.xaml/.cs`：标题和环境标识；侧栏测试标识缩为“隔离测试”防止换行。未改变视觉资源、布局或主题。
- `SmokeRunner.cs`：第二实例测试显式携带--test-mode。
- `RuntimeLocationTests.cs`及测试工程：链接同一纯策略源码，覆盖安全边界和真实SQLite文件。
- `RuntimeLocationValidation.cs`、`Invoke-RuntimeValidation.ps1`：受显式测试模式约束的短时WPF检查/重启；源代码可审查，不是普通启动功能。
- `Package-RuntimeLocation.py`：构建输入快照、最终源码对照、ZIP逐项SHA/CRC及许可证检查；不操作远程仓库或真实数据。
- README、用户说明、升级回退、Release草稿同步数据路径和隔离启动说明。

当前没有独立的“关于软件”窗口；现有窗口/侧栏不再固定显示隔离候选或RC2。程序集仍保留真实预发布版本，未伪装Stable。其他UI文案清理暂不继续。

## 验证边界及遗留事项

- 正式模式不在本机真实用户根目录启动，这是有意遵守安全要求。正式标题用生产同一函数验证；真实WPF截图是明确标识的隔离模式，不能冒充真实用户库验收。
- 本轮未执行真实旧库升级、数据搬运、物理IME、休眠/重启、其他系统DPI或数小时耐久测试；未改变既有计时/统计和15秒保存逻辑，不重新宣称全部硬件验收通过。
- 历史验证脚本有的绑定旧版本并且没有--test-mode；用于新程序会被安全拒绝，不能静默回退。新程序的本轮自动化入口为Invoke-RuntimeValidation.ps1；历史脚本未作为本轮全套复测入口。
- 仍需后续发行文案清理及原有公开仓库/素材权利/隐私/人工验收审批。修复此项不等于已获公开发行授权。
- 本次未修改源码中的受控旧版升级功能，但普通启动不会调用它。
