# 旧版升级与回退指南

**当前只完成隔离演练；真实用户数据库升级须另行授权。** 本轮没有读取、复制或升级正式学习数据库。

## 兼容范围

| 源结构 | 本轮证据 | 结果 |
|---|---|---|
| Schema1，含V0.3.1 | 固定旧结构文件，含旧章节、任务、薄弱点、修订、软删跨日计时 | 升到4并逐字段/原始毫秒对账 |
| Schema2，M1 | 固定Schema2文件及旧学习事实 | 升到4并保留节点ID与状态 |
| Schema3，M2 | 固定结构文件及保留的M2真实合成生命周期数据库 | 包版本、用户修改、绑定与历史对账一致 |
| Schema4，M3/RC | 包与个人改名、学习记录的文件数据库 | 复制校验，不重复执行迁移 |

支持基于结构、application_id和严格语义校验，不声称任意同版本号文件可直接使用。更早产品版本若仍是相同Schema1且通过完整校验可走相同路径，但未对每个历史EXE重复实测。未知版本或结构拒绝。

## 推荐升级流程

1. 在旧版结束/核对活动计时，完整退出窗口及托盘。保留旧程序。
2. 在RC设置页选择「旧版升级到新目录」，明确指定源目录与**从未存在的目标目录**。
3. 程序只读源数据库，通过SQLite Backup捕获一致快照，生成并校验旧格式完整备份。
4. 在独立新目标中执行候选恢复与Schema1→2→3→4增量迁移，再核对原事实、原始毫秒及相应目录/知识包表指纹。
5. 只有验证完成后日志才为Complete，允许新版打开。当前窗口不自动切换。关闭后用指定新目录启动。

目标目录原子独占创建，预检后别人新建的目录也不得复用。运行实例、文件锁、损坏库、活动计时、磁盘空间门槛不足或已有目标都会拒绝。预留估计为数据库四倍加64MiB，仍不能保证底层介质不会中途写失败。

目标中的 `upgrade-evidence/before-upgrade.yanjibak` 是可供旧程序恢复的原格式完整备份；`original.sqlite`为同次验证快照。不要删除操作日志与失败证据。不要把格式4恢复备份当成可交给旧版的格式1备份。

## 失败、重复与启动失败

源目录始终保留原格式。Pending、Failed或损坏操作日志使新版拒绝打开该目标，避免把空库或部分流程误当完成。保留失败目标，使用另一个全新目标重试；不能在原目标重复覆盖。

若升级已经完成但新版启动失败，先保留目标及日志，仍可用原目录和旧程序继续；也可按下文从验证备份恢复一个新的旧格式目录。不要降低user_version骗过旧程序校验。

## 原格式回退

设置页「原格式回退」选升级前.yanjibak与新的回退目录。程序先冻结一份输入快照，锁定后完成校验和解包，防止验证与恢复间被替换；原样保留Schema，不运行迁移。已有目录一律不覆盖。

用对应旧程序打开该新目录。本轮已由保留的V0.3.1真实程序成功打开原格式Schema1回退文件。**旧程序不能直接打开Schema2/3/4**，回退需完整的旧格式数据。

升级后新增的学习先另行完整备份；回退旧快照不会自动合并这些新记录，不得宣称没有时间范围上的取舍。

## 实验边界

已覆盖真实文件锁定、实际损坏文件、重复目标、目标竞争、备份路径替换、迁移故障及实际程序启动。空间不足是预检输入模拟；中断/写失败是隔离故障注入。未真实耗尽磁盘、断电、休眠、重启或升级真实用户数据。
