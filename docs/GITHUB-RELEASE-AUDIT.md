## G1：依赖与运行时安全

初始候选使用.NET/WindowsDesktop **10.0.12**。官方NuGet漏洞数据将这两个实际自包含runtimepack命中16条公告；普通应用NuGet依赖本身没有命中。必须审查`runtimepack.*`，不能只运行普通package引用列表就宣布无漏洞。

重点实例：[CVE-2026-96235微软WPF公告](https://github.com/dotnet/announcements/issues/483)明确影响WindowsDesktop10.0.0～10.0.12，修复10.0.13。[CVE-2026-96960](https://github.com/dotnet/announcements/issues/490)说明相关XML修复和自包含应用需重新部署。这里确认版本受影响，**没有声称研迹工作流可直接利用该漏洞，也未实施利用实验**。

本轮仅在应用csproj固定`RuntimeFrameworkVersion=10.0.13`，从官方NuGet获取项目私有缓存包，重新publish一次。没有升级其他锁定依赖、安装系统SDK或改Windows设置。两运行时包许可与NOTICE和既有文件逐字节相同，机器清单版本已更新。

`tools/Audit-Dependencies.py`比对全部Git锁文件及实际YanJi.deps.json中的普通包与runtimepack，支持稳定/预发布版本区间。新包共21组包版本，当前官方feed **0命中、0不支持区间**；这不是不存在未知漏洞的证明。原始feed、哈希和版本匹配保留在dependencies-with-runtime / dependencies-patched。数据索引来自[NuGet官方漏洞服务](https://api.nuget.org/v3/vulnerabilities/index.json)，抓取日期见本轮证据。

SDK原生命令`dotnet package list --vulnerable --no-restore`因历史Probe项目缺资产文件返回1；没有为让命令变绿而恢复所有工程，而是保留错误并用完整锁文件+实际运行包独立审查。构建工具链仍是私有SDK10.0.401，未随程序分发；公开构建建议安装已修补的10.0.402或更新补丁。没有将SDK本身宣称为已完成所有安全检查。

- SQLite采用短连接、参数化值、事务、WAL与FULL同步；恢复验证完整性、引用和实际Schema，表/索引/触发器定义必须匹配预期Schema。恢复前备份及File.Replace回退保留。
- 完整备份ZIP只接受database.sqlite与manifest.json，限制展开大小512MiB和64KiB；固定目标文件，未将任意条目路径直接用于恢复。校验哈希不是可信来源签名；备份无加密。
- 知识包是纯UTF-8 JSON，16MiB、结构深度/数量/字段/重复ID/环/URL等校验，不执行插件、JS或XAML。安装/更新使用事务与稳定ID/三方冲突机制。
- 没有发现产品工作流的HttpClient/WebClient/Socket、遥测上传、在线账号或自动更新连接。开发Skill、构建NuGet、源码参考网址、系统和用户自选同步目录不等于产品离线性承诺覆盖的全部环境。
- CLI包含开发诊断入口，不能把这些开关当普通使用方式。部分历史入口的隔离约束弱于新验收入口，误用已有数据目录存在风险；本轮不对真实数据试验，公开前应决定是否收紧/分离开发入口（P2）。双击运行的默认路径不触发诊断。
- CSV对开头=、+、-、@加防护；前导控制字符在不同电子表格中的行为未实测，不宣称完全抗公式注入。只在可信来源备份基础上导出，后续如需收紧应定向验证（潜在风险，未证实利用）。
- 异常详情可能包含本机路径，只在本地界面/显式诊断输出出现；README/Issue模板要求脱敏，不上传日志或数据库。没有发现自动将这些详情发送远端。
