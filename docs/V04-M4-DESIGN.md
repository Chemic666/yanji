# M4 发布安全设计

## 版本与历史依据

M3 HEAD39e6ba4包含产品代码2ebe0b9及六份交付文档，二者无产品差异。M0五份设计是2026-10-14的历史事实与建议，并非当前实现清单；本轮原样提交，以M1～M3代码及迁移为当前事实。M0建议的额外档案版本列、删除状态、选择器VM等未全部采用，不为满足旧草案在稳定性阶段扩展结构。

## 升级方案比较

- 原地升级：复用现有候选/替换/回退机制，但需要覆盖进程中断、WAL和启动失败的源替换边界，真实源风险更高。
- **推荐升级复制**：只读旧源，SQLite Backup生成一致旧格式完整备份并验证；在全新目标库调用既有候选恢复迁移；前后原事实指纹对账；成功标记后才允许应用打开。旧源不替换，回退始终有原目录与原格式备份。代价是多一份目录和明确的新旧使用选择，当前更合理。

支持格式1（含V0.3.1）、2、3、4，严格application_id/Schema/语义；拒绝未知、损坏、活动计时、运行实例或非空目标。相同目标重复执行拒绝，不追加迁移。空间门槛在写前检查，不能以注入异常声称真实磁盘满测试通过。

升级操作日志记录Pending/Complete/Failed及备份、前后指纹。任何未Complete目标都拒绝普通启动，包括数据库已迁移而应用未成功启动的情况；人工可保留目标并用另一个新目录重试。成功目标启动失败时原源与验证备份不变，不需要用旧程序打开Schema4。

原格式回退入口只向新的空目录解包已经校验的原格式备份，不执行任何Schema迁移。禁止降低user_version、覆盖源目录、合并新旧学习事实。升级后新增学习先备份保存，不宣称可无损合并回旧版。

## 普通启动与首用

RC双击默认使用独立的YanJi-RC-v04目录，永不自动接管正式YanJi目录。首用界面明确候选状态，可配置默认2028考试档案、日期与使用科目；所选科目归档仅影响新记录选择，不移除历史成员关系。保留现有Quiet Focus样式和编辑器。

设置提供升级复制/原格式回退的明确确认与结果，目标必须新目录，用户无需执行内部验证脚本。开发者本轮只对合成路径调用这些操作。真实用户升级和正式安装路径仍等待单独授权。

## 验证边界

高风险：真实文件SQLite的格式1～4、含包/用户修改、历史修订/删除、原始毫秒、故障/锁/损坏/恢复、旧程序拒绝和原格式回退。正常WPF真实链路覆盖修改入口，原时间状态机不重写。

最终一次原生程序验收与全量核心回归；沿用已证实且未受影响的M3三模式时间计算/10k性能证据，同时对新闭环采样。其他DPI尽量用进程内安全缩放验证并明确不是系统DPI切换；物理IME、真实电源与干净机无证据时NOT TESTED。

不引入账号、在线依赖、公开发布、V0.5功能或新运行库。开源项目根许可若未指定，列为公开发布前需要用户决策，不伪造授权。
