# YanJi V0.2 双方向规范

## 输入与审计证据

产品事实：WPF/.NET 10，本地学习记录；2028 年入学，考试日期未知；计时、补录同一事实来源；无连续打卡要求。本轮范围由用户明确限定为 Today/Statistics 的双方案。

实际基线 f8e5cd8，真实窗口 HWND + Native PrintWindow，2400×1600 物理像素（1200×800 DIP，本机 200%）。`artifacts/latest-v02-baseline.txt` 定位四张原始截图。独立复制以前的测试数据库；没有访问用户数据。

视觉问题（审计判断）：
- 三张等权大卡让今天的核心行为与周/月背景信息争夺注意力，首屏拥挤；不是色彩问题。
- 计时面板的空白备注输入和并排下拉框拉长视线，时间与选科脱离；开始/暂停/结束同时出现形成操作噪声。
- 今日记录行反复显示贡献、整次、来源、日期、章节、说明；删除按钮直接暴露，每行消耗过多高度。
- 统计页面把大筛选卡、三张指标卡放在图表之前，空间分配倒置；次要统计说明和精确到毫秒的大字竞争。
- 所有内容都用同种边框、圆角、白色卡，缺少桌面工作区的层次；侧栏208 DIP、28号粗标题、频繁小标题，内容空间受挤。
- 默认 Fluent 输入与定制按钮/图表在视觉节奏上不一致；深色偏冷蓝，亮青主按钮显眼，长期专注氛围较弱。
- 数据图表正确且可下钻，是应保留的能力；问题是结构、标记密度与展示精度的层级。

## A：静桌 Quiet Desk（推荐候选）

暖纸色 + 鼠尾草，176 DIP 带文字导航；不对称的专注面板/今日账本。只有计时区有柔和抬升，记录与笔记依靠间距和细分隔。统计采用编辑式总时长、每日堆叠 + 科目环形及列表。主次明确，适合长期学习。

## B：专注工作台 Focus Studio

矿物灰 + 石板蓝，64 DIP 图标轨道 + 页内文字导航；左侧计时控制台、右侧紧凑工作日志。统计用通栏日趋势/实际科目投入条 + 原始记录表，强调精度和数据密度。结构、导航、图表主角不同于 A。

危险动作红色独立语义，但不作常驻高亮。数据科目用固定顺序的柔和绿/蓝/赭/紫，辅以文字和图例，不能只靠颜色识别。

字体：Segoe UI Variable/Segoe UI，中文 Microsoft YaHei UI 作为回退；数字 Segoe UI Variable Display，启用 Tabular NumeralAlignment。正文13/14、辅助11/12、分区16/18、页标题26/28、统计总值38、时钟48–58；精确原始毫秒保留在 Tooltip/明细，不强迫全部大字完整输出。简化展示明确使用 ≈，少于分钟使用秒。

间距：4/8/12/16/24/32；主内容24–32，表行48–58。圆角：输入8、选择条8、主要专注表面18、辅助条6。避免层层卡片；分隔线只表达分区或表格，阴影仅用于浮层。小窗口收紧导航、标题、时钟及内边距，保留两列；垂直滚动而非全页缩小；最小900×600，图表保证实际刻度不变。

图标：统一原生 Path，1.5 DIP 描边，18–20尺寸；图标轨道44×44目标，名称/Tooltip/UI Automation 同步。按钮主操作有填色，次操作文字/淡底；危险操作放详情里并确认范围。hover、pressed、disabled、keyboard focus、空态、校验状态明确。淡入120ms可关闭，不使用滚动特效、玻璃模糊或计数动画。

图表：从 StudyAnalytics 原始毫秒聚合；Y轴实际小时/分钟，不归一化每天；零值可见空态，单点非虚构曲线，极值轴自动适配。悬停/键盘可看精确值；点击日期/科目打开同范围原始记录。自然日日均和学习日日均标明不同分母；无未来日期扩大分母。

## Taste-Skill 核实与取舍

本机全局 Skill/catalog 未安装也未自动加载两个名称。项目只保存经审查的固定文本副本并人工读取，无安装脚本执行。
上游 [taste-skill](https://github.com/Leonxlnx/taste-skill)，提交 d237dd399d57524945c0c81327da5da19f7a468d，plugin.json版本1.0.0，MIT；个别 Skill 无独立版本号。完整来源/hash见references/taste-d237dd3/provenance.json。

[redesign-existing-projects](https://github.com/Leonxlnx/taste-skill/blob/d237dd399d57524945c0c81327da5da19f7a468d/skills/redesign-skill/SKILL.md)：采用先审计/保留技术栈、破除均分卡片、数字层级和完整状态。
[high-end-visual-design](https://github.com/Leonxlnx/taste-skill/blob/d237dd399d57524945c0c81327da5da19f7a468d/skills/soft-skill/SKILL.md)：采用暖色编辑式/冷色结构式空间、精细线条和克制强调。拒绝其 React/Tailwind/GSAP、假定高级字体已装、强制巨幅留白/双套边框/玻璃/电影滚动；桌面操作效率和用户要求优先。

当前 App 没有 WPF UI/LiveCharts/ScottPlot 强制外观依赖；使用 Fluent ThemeMode + 原生控件和自绘图表。因此限制来自现有样式/布局，而非库。不新增第三方 UI 库；把原则转成 XAML tokens/control templates、原生 Grid/DockPanel 和 DrawingContext。

尚未验证的假设：暖色编辑式更适合用户长期学习；B 的密度更适合高频回顾。最终由用户对实际两套样板选择，不预先推广。
