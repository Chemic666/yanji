# V0.3 专注与每日工作流

## 需求事实
正式产品基线 V0.2.2；保留该标签与 V0.2.3 小修标签。开发分支继承 V0.2.2 及已完成的显示小修，不重新开展视觉改造。仅实现 V0.3，不提前实施知识模板、错题/模考、云端或公开发行。

## 产品默认与验收
- 自由计时沿用原模式；倒计时默认 45 分钟；番茄钟默认 25 分钟专注、5 分钟休息。专注时长可选 1～720 分钟，休息 1～60 分钟。不是考试计划或学习成果事实。
- 到达目标后只保存目标内可信的有效区间；延迟回调不额外计时。暂停与异常未知间隙不推进目标。未知时间核对后保持暂停，用户主动继续。
- 番茄结束后显示休息倒计时；休息不生成 StudySession，用户主动开始下一轮。休息暂停、跳过与重新启动可用；重启应用不恢复休息倒计时，不据此生成任何学习数据。不强制长休息、自动循环、连续打卡或声音通知。
- 今日展示未完成且到期/无日期的任务；计划页也可一键开始。任务有有效科目则选中它，无科目则使用当前计时科目并明确提示；归档科目禁止新开始。活动计时期间不允许替换任务、科目或模式。
- 任务关联保存稳定 ID 和开始时标题快照。结束计时不会自动完成任务；明确点击完成才更改待办状态。记录详情可以查看任务与模式，历史修正不能丢失关联。
- 迷你窗口共享同一 ViewModel、计时状态和命令；关闭只隐藏窗口。主窗关闭进入托盘的原规则保留。快捷操作只在研迹窗口生效：Ctrl+Enter 开始，Ctrl+Space 暂停/继续，Ctrl+M 迷你窗，Ctrl+L 快速补录。编辑框输入不截获启动/暂停快捷键。避免占用全系统热键。

## 技术方案
沿用 TimerMachine 的 awake/boot/wall 证据判断，仅在可信 Advance 中增加目标上限。FocusContext 是计时模式/目标/任务的元数据，不是时长事实。TimerSnapshot 添加可选字段；StudyRecord 添加可选关联投影。

不改变 schema 1。用现有 settings 中保留的 focus-session:<sessionId> 键保存关联，必须与 sessions、parts、active_timer 一起在 SaveTimer 同一事务提交。ReadRecords 左连接关联；历史编辑保留关联，备份校验核对 active_timer 与关联一致。无关联的旧记录不变。关联损坏应报错，不能按空关联静默处理。记录统计仍只由有效 parts 聚合。旧版本忽略新元数据，不建议用旧版继续编辑新版本活动计时。

休息是独立非学习状态，使用连续 awake 采样；检测电源/时间异常则暂停休息，无未知时长自动确认。无数据库迁移和额外包依赖。

## Skill 应用

## 有界验证与阶段
1. 固定提交 Skill 审查、安装、专属领域规则及使用证据。
2. 目标上限、暂停/恢复、异常及任务关联的针对性核心与持久化测试。
3. 今日任务/模式、迷你窗口、快捷操作，真实 WPF 浅深主题 1200×800 与 900×600 截图。
4. 一次核心回归，隔离进程启动/单实例/托盘/重启恢复及备份校验。失败修复后仅重测受影响范围。

设计按用户自主授权由工程方收敛并自审，不要求逐阶段审批。开源公开发布和许可证选择在 V1.0 前另行审查；本轮不推送远程、不虚填个人信息。
